## Interaction Contracts

### Settings Screen Data Loading (D-03)

| State | Role Badge | Organization Name | Visual Behavior |
|-------|-----------|-------------------|-----------------|
| Query loading | "Member" (fallback) | "Your Organization" (fallback) | No loading spinner -- fallback text prevents layout shift |
| Query success | Actual role, capitalized (e.g. "Owner", "Technician", "Manager") | Actual org name (e.g. "Acme HVAC Services") | Text updates in-place, no animation |
| Query error | "Member" (fallback) | "Your Organization" (fallback) | Silent fallback -- no error toast or indicator. Non-critical data. |
| No active org | Hidden (no badge shown) | "No organization" | Existing behavior preserved |

**Design rationale:** The settings screen is not mission-critical. Showing fallback text during loading is preferable to a loading spinner that delays the entire screen render. The home screen already established this pattern (`orgQuery.data?.name ?? "Aucta"` with no loading state).

**Role capitalization rule:** The API returns lowercase role strings ("owner", "technician", "manager", "member"). Display with first letter capitalized. Use a simple capitalize transform: `role.charAt(0).toUpperCase() + role.slice(1)`.
