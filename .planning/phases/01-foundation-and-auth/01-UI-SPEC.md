# Phase 1 — UI Design Contract

> Visual and interaction contract for the mobile app shell: auth screens, onboarding, org setup, and home screen. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (mobile phase -- shadcn is web-only, deferred to dashboard phases) |
| Preset | not applicable |
| Component library | react-native-reusables (shadcn philosophy for React Native, NativeWind-based) |
| Icon library | lucide-react-native |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding between icon and label |
| sm | 8px | Compact element spacing, input inner padding vertical |
| md | 16px | Default element spacing, input horizontal padding, card padding |
| lg | 24px | Section padding, spacing between form fields |
| xl | 32px | Layout gaps between major sections |
| 2xl | 48px | Major section breaks, screen top/bottom safe-area padding |
| 3xl | 64px | Page-level spacing, home screen CTA vertical offset |

Exceptions: 56px for primary touch targets (56x56dp minimum per UX-01, established in Phase 1 for consistency even though UX-01 is Phase 3). 44px for secondary touch targets (tab bar icons, nav buttons).

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 16px | 400 (regular) | 1.5 (24px) | Form labels, instructional text, settings items |
| Label | 14px | 600 (semibold) | 1.4 (20px) | Input labels, tab bar labels, secondary info, error messages |
| Heading | 20px | 600 (semibold) | 1.2 (24px) | Screen titles ("Welcome back", "Create organization") |
| Display | 28px | 600 (semibold) | 1.15 (32px) | Home screen greeting, org name display |

Font family: system font stack only. No custom font files. iOS renders SF Pro, Android renders Roboto. Both are optimized for readability at the declared sizes.

## Interaction Patterns

### Form Submission
- Button shows inline loading spinner (replaces label text) during async operations.
- Button is disabled while loading. Opacity reduced to 0.7.
- On error, the relevant input field shows a red border (#DC2626 / #EF4444) and error message text below in Label size (14px, destructive color).
- On success, navigate to next screen immediately. No success toast on auth flows.

### Invite Code Entry
- Characters auto-uppercase on input.
- Each character cell highlights with accent border on focus.
- After 6 characters entered, automatically trigger "Look Up Code".
- Invalid code shakes the input row (horizontal oscillation, 300ms).

### QR Code Scanning
- Camera fills the screen. A centered square frame (250x250px) guides the scan area.
- On successful scan, navigate to join preview screen.
- "Enter code manually" link at bottom for fallback.

### Theme Toggle
- Located in Settings screen.
- Segmented control: "Light" / "Dark" / "System".
- Theme change applies immediately, no restart required.

### Keyboard Behavior
- Keyboard avoidance: screen scrolls to keep active input visible.
- "Next" keyboard action between sequential form fields (name -> email -> password).
- "Done" keyboard action on the final field.

## Accessibility

| Requirement | Implementation |
|-------------|----------------|
| WCAG AAA contrast | All text/background combinations verified above (minimum 7:1 for normal text, 4.5:1 for large text) |
| Touch targets | Primary actions: 56x56dp minimum. Secondary actions: 44x44dp minimum. |
| Screen reader | All interactive elements have `accessibilityLabel`. Images have `accessibilityRole="image"`. |
| Reduced motion | Loading spinner respects `prefers-reduced-motion` (static dot indicator fallback). |
| Font scaling | Layouts accommodate up to 200% system font scaling without clipping. |

## Design Token Export

Design tokens are defined in `apps/mobile/constants/theme.ts` and consumed by NativeWind v4 via `tailwind.config.js`. Both light and dark themes reference the same token structure.

```
// Token structure (reference only -- executor implements)
colors.background    = dominant
colors.surface       = secondary
colors.accent        = accent
colors.destructive   = destructive
colors.text.primary  = text primary
colors.text.secondary = text secondary
colors.border.default = border default
colors.border.focus   = border focus
```

When the web dashboard is built in later phases, tokens will be extracted to `packages/config/design-tokens.ts` and consumed by both Tailwind v3 (mobile) and Tailwind v4 (web) configs. For Phase 1, tokens live in the mobile app only.
