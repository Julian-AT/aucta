```typescript
// Persist findings to database via tRPC (KB-07)
for (const fc of toolCall.functionCalls) {
  if (fc.name === "logFinding" && serverSessionId) {
    const response = result.functionResponses.find(
      (r) => r.id === fc.id,
    );
    if (response?.response && !response.response.error) {
      addFindingMutation.mutate({
        sessionId: serverSessionId,
        category: String(fc.args.category),
        description: String(fc.args.description),
        severity: String(fc.args.severity),
        equipmentModel: fc.args.equipmentModel
          ? String(fc.args.equipmentModel)
          : undefined,
        manufacturer: fc.args.manufacturer
          ? String(fc.args.manufacturer)
          : undefined,
      });
      store.getState().incrementFindingsCount();
    }
  }
}
```

Key details:
- Use `.mutate()` (fire-and-forget), NOT `.mutateAsync()` -- finding persistence must not block the audio stream
- Cast `fc.args` fields with `String()` because Gemini function call args are typed as `Record<string, unknown>` from the mobile side. Server-side Zod validation (CreateSessionFindingDTO) will catch malformed data.
- Use optional chaining on response to handle edge cases where tool call response is missing
- Place this INSIDE the existing `if (serverSessionId)` block but AFTER the tool call persistence loop
